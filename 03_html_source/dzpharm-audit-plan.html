Section 00

Verify these thirteen things before you plan a single sprint

The 62 reports were written over three days and the later ones corrected the earlier ones without the earlier ones being withdrawn. Eleven findings now contradict each other, and two features were never reviewed. Planning on contradictory evidence burns engineering time on bugs that were already fixed and leaves real ones untouched. This is half a day of work and it is the highest-value half day in the plan.

The AI layer

A Gemini Flash Copilot grounded in the DzPharm dataset rather than generic pharmacology — it answers Algerian regulatory questions (Liste I versus Liste II) that a general model cannot. It is trilingual with genuine Darija support, not just Modern Standard Arabic: دوا تاع السكر؟ is understood. Three audience modes exist; one of them does nothing (see P1-19). Output is structured into four clinical sections with LaTeX dose maths and Algerian brand names. Around it sit voice dictation, four suggested prompts, feedback buttons and text-to-speech.

The design system — the second moat

This is the part the main report under-rated and the later reports corrected. Roughly 400 CSS custom properties across 12 semantic categories with dark and light values swapped atomically. A 7-level clinical state system that encodes severity as colour and text and icon. A 20-palette Nuancier with named cultural identities — Craie & Cobalt, Dune & Cèdre de l'Atlas, Perle & Azur d'Alger. An 8-step type scale with calc()-derived line-heights that correctly gives small text proportionally more leading than large text, six weights, five tracking levels. A 4px grid with ten container widths, four radius tokens, ten z-index layers, a Radix-pattern focus ring. 118 Lucide icons across 52 names and not a single raster image. Eleven of twelve contrast pairs pass AAA.

Worth saying plainly

A team that ships schema-versioned Zustand persistence, calc() line-heights and a correct ARIA combobox did not build this carelessly. The defects in this document are the debts of speed, not of skill — which is exactly why they are all cheap to clear.

Navigation, discovery and infrastructure

  • Répertoire — 7-column sortable table over 9,555 records, five faceted filters with reference counts, table/card toggle, one-click CSV export with UTF-8 BOM and French semicolons.
  • Prix & Chifa — unified medication and parapharmacy catalogue with PPA, class, registry status and CSV export.
  • Interactions — sequential checker plus an N×N matrix using the official ANSM/MIPH 4-level classification, with five pre-loaded example pairs covering the five outpatient interactions that kill people.
  • Command palette — 23 commands, eight single-key hotkeys, dual-source search across both the drug database and the command list, emergency numbers ordered first.
  • Emergency banner — SAMU 14, Protection Civile 102, Police 17, Anti-Poison, as real tel: links, collapsible, persistent.
  • Audience modes — Pro / Famille / Botanique, the last tied to a Pharmacopée Royale of traditional and herbal knowledge. Nobody else in the market has this and no report examines it.
  • Infrastructure — Next.js App Router on Turbopack, Tailwind v4, Vercel Edge, next-themes, Zustand with schema-versioned persistence, Sonner, Lucide, a v8 service worker with tested offline mode.
Section 02

Where I disagree with the source reports' priorities

The reports graded each feature in isolation. Severity is not a property of a feature — it is a property of what happens to a person when the feature fails. Four items move up, three move down.

Moved up to P0

  • The command palette selection desync was filed P2 polish. Arrow down to Centre Anti-Poison, press Enter, and the platform dials SAMU instead. A pharmacist reaching for the palette is by definition in a hurry. Dialling the wrong emergency service is not polish. P0-11
  • Hard-coded fr-FR speech recognition was filed P1. An Arabic speaker dictates a dose, the engine maps Arabic phonemes onto French, and the resulting nonsense is sent to a clinical model with no review step. A confident, well-formatted answer to a question nobody asked is more dangerous than an error message. P0-10
  • No mandatory review after dictation. "22 kilos" heard as "20 kilos" is a 10% dosing error delivered with full model confidence. P0-10
  • Palette-mutable clinical colours, if V13 confirms it. A contre-indication that is not red in one of twenty palettes is a dispensing hazard. P0-12

Moved down

  • "Add a toast system" and "add an error region on login" — both already built and working. Deleted from the backlog entirely.
  • Native mobile apps. The reports place this in the high-impact quarterly roadmap. Wrapping a PWA whose routing is broken in Capacitor ships the breakage to an app store review. Deferred until routing and accounts land.

One thing the reports got exactly right, and it bears repeating

Two changes — routing and accounts — unblock roughly twenty other items between them. Routing alone resolves state management, SEO, PWA installability, sharing, the medication detail URL, and the browser history contract. Accounts alone unblock Copilot history, recently-viewed, favourites, notification targeting, cross-device sync and the audit trail. Nothing else on this list has that leverage. Do them first and half the register collapses.

Second-order chains

  • Streaming before history. Ship the Vercel AI SDK first, then persist. Persisting a batch-render message shape means rewriting the persistence layer when streaming lands.
  • Coverage before maps. Do not build a proximity map for Pharmacies de garde while 41 of 58 wilayas are empty. A map of nothing is worse than a list of something.
  • Interaction list state before the Chifa and comparator fixes. All three share the drug-selection component; the Chifa bug that routes clicks to the Comparator is almost certainly the same shared component. Fix it once.
  • Contrast audit before new palettes. Do not add the twenty-first Nuancier palette until the first twenty pass AA in both themes.
  • Accounts before anything that syncs, bills, or claims regulatory compliance.
Section 05

The execution plan

Seven phases. Phase 0 is half a day. Phase 1 is one day and buys back nine grades. Everything after that is real engineering. Sized for two engineers plus a part-time designer; a solo builder should read the sequence and stretch the calendar, not reorder it.

Phase 0 — Settle the record

Half a day
Goal: stop planning on contradictory evidence
  • Run all thirteen checks in Section 00 against the current build. Record the commit SHA.
  • Close as already-fixed: the toast system, the login error region, the lock button, server-side auth validation, and whichever of manifest/matrix/share/cap V1, V2, V3 and V6 disprove.
  • Answer V13 first. If palettes can recolour clinical severity, everything else waits.
  • Find out what features #20 and #21 are. Add the three bonus tools and the prescription-paste tool to the menu.
  • Re-measure performance on throttled mobile, not warm European edge.

Phase 1 — The one-day sweep

One day
Goal: every fix under one hour, all in one pull request

Twenty-three items, roughly seven working hours, no dependencies, no architecture. It clears two WCAG failures outright, gives the platform a stable brand identity for the first time, makes Arabic readable, and turns three sets of dead buttons into working ones. Ship it before you plan anything larger — it changes how the product feels, and it will change how you feel about the rest of this list.

Order within the day: reduced motion (5 min, benefits ~35% of users) → aria-labels → dir="rtl" → webfonts → the three dead-click wirings → the metadata and robots fixes → the focus and layout polish.

Phase 2 — Routing

Two weeks
Goal: 9,555 pages that exist at a URL
  • Days 1–3. Add app/repertoire, app/interactions, app/prix-chifa, app/copilote alongside the existing setState navigation. Both paths work. Nothing breaks.
  • Days 4–5. Feature-flag the header behind NEXT_PUBLIC_USE_ROUTER. Ten percent of sessions get <Link>. Watch for back-button errors and lost state.
  • Week 2, days 1–3. Ramp to 50 then 100. Delete the setState path. Move the twelve clinical tools to /outils/[tool].
  • Week 2, days 4–7. /medicament/[slug] with generateStaticParams over all 9,555 records, plus the intercepting-route pattern so the modal behaviour survives while the URL changes. Then the branded 404, the dynamic sitemap on the correct domain, canonical tags, per-medication OG images, and the manifest link.
  • The day it ships. Submit the sitemap to Search Console. Indexing takes two to four weeks; start the clock.

Carry the state-management fixes in the same fortnight — the interaction drug list into the URL, Copilot history into Zustand v3, and a storage event listener for cross-tab sync. Roughly 150 lines, and they close the three most expensive data-loss paths on the platform.

Phase 3 — Identity

Two to three weeks
Goal: the platform knows who is using it
  • Day 1. NextAuth with the existing shared code as a Credentials provider. The code moves to an environment variable, the session becomes an httpOnly cookie. Cross-tab sync and the client-side bypass both close for free.
  • Week 1. Rate limiting on the auth route. Idle timer with a fifteen-minute lock. Lock that preserves the Zustand store so a pharmacist called away does not lose a six-drug interaction check.
  • Weeks 2–3. Per-user accounts. Email plus passkey — prefer WebAuthn over TOTP; it is better security and far better ergonomics on the phone a pharmacist already holds. Roles: titulaire, assistant, médecin, étudiant, patient.
  • Then. Migrate favourites, recently-viewed and Copilot history server-side. Audit log writing every lookup, every Copilot query and every tool use against a user ID.

Announce seven days ahead. Keep the shared code alive for thirty days as a fallback. Send magic links to known power users before the cutover.

Phase 4 — Make the Copilot trustworthy

Two weeks
Goal: the signature feature stops feeling like a demo
  • Vercel AI SDK — streamText and useChat. Eleven seconds of frozen UI becomes half a second to first token, plus a working cancel button. This is the single largest perceived-performance change available anywhere on the platform.
  • Persist conversations. Thread list, titles, export to Markdown and PDF through the existing print pipeline.
  • Fix Mode patient — it currently emits the same DCI-and-LaTeX output as Mode pro. Write a real system prompt with a reading-level target and no jargon, then verify with the same query in all three modes.
  • Persist the mode to Zustand so it stops resetting to "pro" on every load.
  • Voice: FR/AR toggle, permission pre-prompt, state-aware stop button, and a mandatory review beat before a dictated clinical query is sent.
  • Chunked TTS so long clinical answers can be listened to while examining a patient.
  • The four missing live regions, so screen-reader users learn that an answer has arrived.

Phase 5 — Repair what is already built

Two weeks, parallel
Goal: nothing on the platform is a dead end
  • Shortage submit 500 — the community pipeline is the platform's only two-way public-health channel and it is currently closed. Check Vercel logs, fix, add a success toast, add rate limiting, add a Résolu state.
  • Chifa drug-addition routing to the Comparator. Almost certainly a shared search component with the wrong handler bound. Fix once, verify in all three consumers.
  • Parapharmacie filter returning zero rows — 675 products currently unreachable. Likely a category field mismatch.
  • 100-per-page rendering only 40 rows. Ramadan "Copier le plan" failing. Répertoire sort direction not toggling. Card view rows not keyboard reachable. The empty Paramètres placeholder — remove it or build it.
  • Search: fuzzy matching, recent queries on empty focus, match highlighting. "dolipran" returning nothing is the most common failure a real user will hit.

Phase 6 — Accessibility and internationalisation, properly

Three to four weeks
Goal: WCAG 2.2 AA certified, and readable in Arabic
  • Full next-intl adoption. Arabic UI translations. RTL as a first-class layout using CSS logical properties, not mirrored margins. A language switcher in the header.
  • All twenty Nuancier palettes tested in both themes against AA contrast and against deuteranopia, protanopia and tritanopia. Fix the failures. Menthe at 2.1:1 on light is already known to fail.
  • Lock clinical state colours out of the palette system permanently.
  • Répertoire table reflow to cards at 320px. Remaining px values to rem. Fixed heights to min-heights.
  • Screen-reader passes with NVDA, VoiceOver and TalkBack — in French and Arabic.
  • axe-core in CI at zero violations. Lighthouse CI budgets. Playwright end-to-end on login, search and medication detail.
Section 06

Definition of done

An item is closed when someone other than its author can reproduce the acceptance test in the register. Not when the pull request merges.

Every pull request

  • TypeScript strict. ESLint and Prettier clean.
  • axe-core scan: zero violations on every page the change touches.
  • Lighthouse CI: performance ≥ 95, accessibility ≥ 95, best practices ≥ 95, SEO ≥ 90.
  • Initial JS budget 120 KB. Current baseline is around 85 KB — protect it.
  • Keyboard-only pass on the changed surface. Unplug the mouse.
  • Both themes. Both languages once i18n lands. 320px and 200% zoom.

Any pull request touching clinical output

  • A pharmacist reviews the content. Not the engineer who wrote it.
  • Every dose calculation is verified by hand against an independent source.
  • The change is dated and attributed in a clinical changelog.
  • Prompt or model changes run against the evaluation set before merge. If you do not have one yet, building it is Phase 4's real deliverable — two hundred Algerian clinical questions with expert answers, run on every change. Without it you cannot know whether a prompt edit made the Copilot better or worse.

The one-line version
