SECTION 01

Executive summary — the whole picture on one screen

DzPharm is a technically excellent, clinically ambitious platform — 9,555 medication records, a trilingual Darija-capable AI Copilot, 17 tools, a ~400-token design system, and top-decile performance — wearing a prototype's skeleton. The defects are debts of speed, not of skill, and every one of them has a scoped fix.

✓ What is genuinely strong (protect at all costs)

  • Performance crown jewels — TTFB 80 ms, FCP 204 ms, 88.8 KB HTML transfer, 17 resources, zero console errors across 14 screens (but see V9: re-measure on throttled mobile before believing "top decile").
  • The dataset is the moat — 9,555 AMM records, 911 ANSM-format RCPs, 932 DCI monographs across 30 domains, 1,791 parapharmacy products with PPA pricing, 24 source books, 60 same-DCI equivalents on DOLIPRANE alone. No competitor in the Maghreb has this.
  • Trilingual AI Copilot — Gemini Flash grounded in Algerian data (answers Liste I vs II questions a generic LLM cannot), FR/AR/Darija with « دوا تاع السكر؟ » genuinely understood, three audience modes, 4-section structured clinical output.
  • Culturally unique tools — Ramadan chronopharmacology adapter (nobody on Earth offers this), Chifa/CNAS reimbursement simulator, family cabinet (خزانة الأدوية العائلية, the only bilingual UI), Pharmacopée Royale botanical mode.
  • Power-user layer — Cmd-K palette with 23 commands, single-key hotkeys, emergency numbers ordered first; skip-link, ARIA combobox/tablist patterns better than 90% of healthcare sites.
  • The design system is the second moat — ~400 CSS tokens, 7-level clinical state system, 20-palette Nuancier with cultural names, 8-step type scale with calc() line-heights, 118 Lucide icons, zero raster images, 11/12 contrast pairs AAA.

✗ What blocks professional deployment (the eight P0s)

  • P0-01 No real routing — every non-home view 404s on direct URL. Kills deep-linking, sharing, SEO (9,555 pages invisible), back button, refresh.
  • P0-02 Single-factor shared-code auth — one code for everyone (and it is the LOST sequence 4-8-15-16-23-42, i.e. effectively public), sessionStorage-based session, no accounts, no MFA, no audit trail → non-compliant with Law 85-05 traceability and indefensible if a clinical incident occurs.
  • P0-03 Medication detail is a URL-less modal — a pharmacist cannot send a colleague the drug they are worried about.
  • P0-04/05/06/07 Clinical-safety cluster — dictation hard-wired to fr-FR with no review step (Arabic doses become confident nonsense); Cmd-K selection desync can dial the wrong emergency service; Nuancier palettes may repaint clinical severity colours; login error announcement needs verification.
  • P0-08 The Copilot does arithmetic — an LLM computing doses with no deterministic cross-check is the single largest harm vector on the platform.

The five findings this edition adds that no prior document caught

  1. V14 — a fourteenth contradiction: the UX Review documents a 5-scope search filter (Tous / DCI / Marque / Laboratoire / N° AMM), yet the Ultimate Blueprint's P3-15 states search "matches brand name only". Both cannot be true. One is a stale finding; settle it in Phase 0 before building the synonym layer on the wrong assumption.
  2. Stat drift is now a registered defect (P2-28): the corpus quotes 911 DCI monographs in one document and 932 in another (the dataset grew mid-audit); homepage and metadata numbers are hard-coded and will keep lying by degrees. They must be generated from the dataset.
  3. The shared access code must be treated as compromised (folded into P0-02): it appears verbatim in a distributed PDF report, and it is a famous pop-culture number — the two worst properties a secret can have.
  4. There is no measurement stack (P2-25/26): every plan document ends with a KPI table, yet no analytics, error-tracking, uptime monitoring or status page exists anywhere in the corpus. You cannot manage the 380× SEO claim or the <0.05% error gate with manual curl checks.
  5. Domain-before-SEO sequencing (P1-26): the sprint plan submits the sitemap from "dzpharm.dz or the vercel URL for now". Submitting 9,570 URLs on a *.vercel.app host and re-submitting after the domain move wastes the entire indexing runway. Buy the domain in Week 1, or delay submission — but never do it twice.
The verdict in one sentence (carried from the original audit, still true): roughly 6–8 weeks of focused work on routing, authentication, typography and accessibility moves DzPharm from "impressive demo" to "trustworthy clinical infrastructure" — and none of it requires a rewrite; every fix is additive on the existing Next.js + Tailwind + Zustand foundation. This v2 plan says it is 13 weeks to A+ with two engineers (or the same sequence stretched, never reordered, for a solo builder), because the deep-dives doubled the issue count since that sentence was written.

SECTION 03

Verify first — fourteen contradictions to settle before you plan a single sprint

The reports were written over several days and the later ones corrected the earlier ones without the earlier ones being withdrawn. Fourteen findings now contradict each other or were never verified. Planning on contradictory evidence burns engineering time on bugs that are already fixed and leaves real ones untouched. This is half a day of work and it is the highest-value half day in the entire plan. Run each check against the live build, record the answer and the commit SHA, and only then open the register.
